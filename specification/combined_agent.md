# Combined Agent

**Status**: [Experimental](../README.md#versioning-and-status-of-the-specification)

Combined Agents are targeting AppDynamics customers who wish to migrate their APM solution to Splunk O11y Cloud.
These agents offer the traditional AppDynamics functionality but can be also configured to generate Open Telemetry signals.

## Combined Agent Deployment Mode

The functionality of a Combined Agent is defined by its _deployment mode_.
The deployment mode is specified by environment variable `AGENT_DEPLOYMENT_MODE`.
For Combined Java Agent, the deployment mode can also be specified by system property `agent.deployment.mode`, which takes precedence over the environment variable.

The following deployment modes SHOULD be supported.

| mode | behavior | notes |
|------|---------------------------------------|-----------------------------------|
| `appd` | The agent uses AppD specific instrumentation only and sends data to an AppD controller. The OTel specific instrumentation is not applied. OTel signals are not generated. | This is the default mode if environment variable `APPDYNAMICS_OPENTELEMETRY_ENABLED` (or system property `appdynamics.opentelemetry.enabled` for Java) is `false` or is not specified. |
| `dual` | The agent works in **Dual Signal** mode: it uses AppD specific instrumentation to collect APM data for an AppD controller, and uses OTel specific instrumentation to generate OTel signals and sends them to a collector. | This is the default mode if environment variable `APPDYNAMICS_OPENTELEMETRY_ENABLED` (or system property `appdynamics.opentelemetry.enabled` for Java) is `true`. |
| `hybrid` | The agent works in **Hybrd** mode, using AppD specific instrumentation only. It sends APM data to an AppD controller and generates OTel signals from the same instrumentation sending them to an OTel collector. The OTel specific instrumentation is not applied. | The OTel spans and span attributes can be substantially different from those generated by OTel native instrumentation. |
| `otel` | The agent works in **OTel-only** mode: it uses OTel specific instrumentation, generates OTel signals and emits them to a collector. The agent does not apply AppD specific instrumentation and does not attempt to register with any controller. | |

If the environment variable `AGENT_DEPLOYMENT_MODE` (or system property `agent.deployment.mode`) is used, the environment variable `APPDYNAMICS_OPENTELEMETRY_ENABLED` and system property `appdynamics.opentelementry.enabled` are ignored.

In Dual Signal or OTel-only modes, the agent MUST accept and handle all environment variables that control the OTel specific instrumentation, signal processing and exporting as specified by the corresponding Open Telementry [documentation for SDK](https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/) and also environment variables that apply to the Open Telemetry autoinstumenting agent for a given platform.

## Automatic Agent Configuration Migration

In Dual Signal mode or in OTel-only mode, when the user does not provide their own _service namespace_, _service name_ or _deployment environment name_ for the OTel Resource, the Combined Agent SHOULD configure them automatically based on the AppDynamics agent configuration as shown in the following table.

| AppDynamics configuration item | Open Telemetry configuration item |
|--------------------------------|-----------------------------------|
| account name | deployment environment name |
| application name | service namespace |
| tier name | service name |

## Dual Signal mode enhancements

In Dual Signal mode, the agent SHOULD add the following attributes to OTel spans.

| Attribute | Applicability |
|----------|----------------------------------------------|
| `appd.app.name` <br> `appd.bt.name` | Whenever a new Business Transaction starts with the agent, or for ROOT spans. |
| `appd.tier.name` <br> `appd.request.guid` | Whenever a new or continuing Business Transaction starts within the agent, or for ROOT spans. |

AppD snapshots captured in Dual Signal mode SHOULD provide the corresponding current `TraceId` under the *Data Collectors* section.

Notes:
* This functionality assumes certain alignment of AppDynamics and OTel instrumentation and is provided as the _best effort_ only.
* A single OTel trace can contain multiple BTs, if it crosses AppD Application boundary.
* Differences between AppDynamics and OTel instrumentation can cause a single BT instance to be composed of multiple traces.

## Contributing to customer telemetry

When a Combined Agent starts in Dual Signal mode, it SHOULD add Open Telemetry Resource attribute `appdynamics.agent.version` and set it to the actual Combined Agent version. For example, for Combined Java Agent, such value might be `25.3.0.36916`.
